粘包问题：读取指令发送太快
t=0ms    你发指令1
t=0.2ms  指令1到达传感器，开始处理（假设处理需要8ms）
t=1ms    你又发了指令2（因为你上一条读完立刻就发下一条，间隔只有1ms）
t=1.2ms  指令2到达传感器，但传感器还在处理指令1
         → 指令2就排在传感器的接收缓冲区里等着
t=8ms    传感器处理完指令1，立刻发回复1
t=8.1ms  回复1刚发完，传感器立刻从缓冲区取出指令2开始处理
t=16.1ms 处理完指令2，立刻发回复2

1.移除循环内的 reset_input_buffer()：这是你当前丢帧、粘包处理失效的根源 —— 每次发指令前清空所有缓存，会直接丢弃还没来得及解析的残留数据，且完全无法应对多帧堆叠的粘包场景。
2.新增持久化接收缓冲区：用 bytearray 持续累积所有读到的串口字节，数据到达就追加，解析出完整一帧再移除对应字节，天然同时支持粘包 + 分包场景。
3.独立帧解析逻辑：封装专门的帧匹配函数，自动找帧头、校验长度、CRC 校验，解析成功就入队，失败自动跳过错位字节，永远不会卡死在错误帧上。
4.收发完全解耦：指令发送按固定时间间隔执行，不再和「等回复」绑定，既可以提升轮询频率，也不会因为接收延迟影响发送节奏。
5.异常兜底：设置缓冲区最大长度，防止异常垃圾数据导致内存溢出。
